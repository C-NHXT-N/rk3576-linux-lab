## 跟着做：解释、预测、操作、观察


### 1. 一个设备可以有多个接口

```bash
ip -brief addr
ip route
ss -lnt
```

接口是网络连接入口，地址属于接口，路由决定发往目标时选择的下一跳与接口。`lo` 是回环，`127.0.0.1` 指本机；Wi-Fi、以太网、虚拟网络可能同时存在。/24 等表示地址前缀，不能直接把任何两个不同地址视为同网段。

`ip route` 的 default 仅在没有更具体匹配等条件下参与选择；策略路由和多个路由表可能影响结果，可用 `ip route get 实际目标IP` 查看本机对一个目标的选择。这里不修改网络设置。

### 2. 在回环地址启动一个自己的测试服务

**先预测：** 只监听 127.0.0.1 的端口能直接被另一台电脑访问吗？

```bash
cd "$RKLAB_ROOT"
python3 -m http.server 8765 --bind 127.0.0.1 --directory docs &
server_pid=$!
ss -lntp | grep ':8765'
python3 -c 'import urllib.request; print(urllib.request.urlopen("http://127.0.0.1:8765/", timeout=3).status)'
```

预期本地请求得到 200。这里的临时 HTTP 服务只用于理解网络，不是教程网站建设或发布。服务若已占用端口会启动失败，应选一个未占用端口并同步修改命令，不要结束未知进程。

0.0.0.0 表示 IPv4 的所有本地地址监听，`[::]` 对应 IPv6 通配地址，是否兼容 IPv4 还受程序与系统设置影响。监听存在不保证远程可达，还需地址、路由、访问控制和服务协议都匹配。

### 3. 停止与验证

```bash
kill -TERM "$server_pid"
wait "$server_pid"
ss -lnt | grep ':8765'
```

最后的 grep 无匹配是预期。ss 的 `-l/-n/-t/-p` 分别是监听、数字、TCP、进程信息；普通用户可能看不到其他用户进程详情，这不是“没有进程”的证据。

### 排错顺序

先确认程序是否运行，再确认监听地址与端口，然后从板上测试协议，最后从电脑检查到板卡的网络路径。域名失败与 IP 连接失败分别排查；不要为解决应用启动失败而盲目改路由。
