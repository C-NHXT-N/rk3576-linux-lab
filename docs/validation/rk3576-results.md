# RK3576 YOLO26n 结项记录

交付采用 YOLO26n FP16 640×640、batch=1。MPP 解码后，CPU 融合预处理写入绑定输入，两个 NPU 核上的四个上下文负责逐帧推理。参考后处理、原地 BGR 绘制和三缓冲 MPP 编码完成标注成片。编码端使用 NEON 转换。

| 对照 | 实测结果 | 决定 |
|---|---|---|
| 初期软件展示与融合检测 | 软件展示约 31–32 FPS，融合检测约 59.6–59.8 FPS | 检测成绩单列，完整展示改用原生 MPP |
| FP16 I/O 绑定 | 真实视频检测由 54.24 提升至 56.88 FPS，CPU 时间由 66.71 降至 44.13 ms/帧，P95 由 148 增至 201 ms | 采用输入和输出绑定 |
| 上下文、在途和绑定方式 | 四上下文、八在途、动态绑定 57.00 FPS。两上下文 53.90 FPS，四在途 56.19 FPS，固定绑定 56.90 FPS | 保留四上下文、八在途和动态绑定 |
| 流水编码与原地画布 | 成片 49.04→51.16／50.75→52.71 FPS，综合 +4.09% | 采用 |
| 缓存编码缓冲与 RGA | 缓存缓冲夜间 +1.19%、白天 −0.51%。RGA 降低约 8%–12% CPU 成本，完整吞吐约 +0.05% | 采用默认编码缓冲和 NEON |
| 双线程、分块和局部 NV12 合成 | 四方向组合中 B 为 51.07／52.49 FPS，全组合为 21.23／32.42 FPS | 保留单绘制线程、参考后处理和原地 BGR |
| 就绪调度与直接 NV12 准备 | B 为 51.08／52.50 FPS。单换 NV12 准备综合 +0.64%，双线程就绪调度慢 4.4%–6.0% | 保留 B |
| 静态矩形 FP16 640×384 | 完整成片 **74.47／77.57 FPS**，同轮 B 为 **51.10／52.25 FPS**，配对综合 **+46.66%**。预备输入推理约 106.58–107.85 次/秒，注入参考检测结果时输出链路约 160–168 FPS | 性能通过，精度门槛未通过 |
| INT8 初测 | 两张有目标的样图末次调用约 44–50→24–25 ms，最差高分框 IoU 约 0.68–0.77 | 保留 FP16 |

表中成对的 FPS 按夜间、白天排列。矩形实验于 2026-11-09 北京时间 17:29:41 完成，14 轮全片完整性与 4 轮推理诊断均通过。28 张独立抽样标注中，白天精确率由 91.30% 降到 87.23%。其中一个远车框的 IoU 从 0.5044 降到 0.4963，跨过 0.50 匹配阈值。夜间基线没有匹配到符合尺寸条件的标注小行人，该项无法判定。综合保留 B 版。

板端保留两段 1050 帧的 720p30 输入、逐帧检测参照和 B 版成片。成片为 1280×790、30 FPS、35 秒，保存于 `projects/04-rknn-vision/run/delivery/night.mp4` 和 `day.mp4`。视频入口与复验见 [视觉项目说明](../../projects/04-rknn-vision/README.md)。

夜间素材为 George Morina 的街景视频前 35 秒。白天素材为 German Korb 的行车视频第 10 至 45 秒。 [夜间原视频](https://www.pexels.com/video/busy-city-street-at-christmas-time-6171340/) · [白天原视频](https://www.pexels.com/video/dash-cam-footage-in-city-driving-4644521/) · [Pexels 许可](https://www.pexels.com/license/)

结项复验通过 70 项板端回归。两段视频单轮实测夜间 51.04 FPS、白天 52.77 FPS，均通过逐帧参照、帧数、规格、编解码 EOS 和缓冲归还检查。

结项清理后，板端视觉项目磁盘占用由 2,644,025,344 字节降至 373,657,600 字节，释放约 2.11 GiB，分区可用约 36.95 GiB。Windows 工作区移除的文件共 1,048,030,070 字节，约 0.98 GiB。
