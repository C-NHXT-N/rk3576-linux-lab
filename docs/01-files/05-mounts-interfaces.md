## 跟着做：解释、预测、操作、观察


### 1. 从设备到可访问路径

```text
块设备 → 分区（也可能直接使用整设备）→ 文件系统 → 挂载点 → 路径
```

挂载把一个文件系统接入当前目录树，不是把内容复制到一个目录里。RK3576 的根文件系统可能来自 eMMC、SD 卡或其他存储，名称与分区号由镜像决定。

```bash
lsblk -f
findmnt /
df -h /
findmnt -T "$RKLAB_ROOT"
```

`lsblk` 描述块设备关系；`findmnt` 说明路径属于哪个挂载；`df` 说明已挂载文件系统的空间。读这三个结果，才能把存储结构与目录树连起来。不要把作者的 mmcblk 编号直接用于自己的设备。

### 2. 并非每个文件系统都来自磁盘分区

**先预测：** `/proc/meminfo` 变化时，是否意味着系统反复改写 eMMC 上一个文本文件？

```bash
findmnt /proc
findmnt /sys
findmnt /dev
head -n 5 /proc/meminfo
ls -l /dev/null
ls /sys/class/thermal
```

| 接口 | 本阶段的认识 | 后续深化 |
|---|---|---|
| `/proc` | procfs 提供进程、内核状态及部分控制接口 | 进程生命周期、文件描述符 |
| `/sys` | sysfs 展示设备模型、属性等信息 | thermal、设备与驱动关系 |
| `/dev` | 设备节点等入口，通常由 devtmpfs 和设备管理机制组织 | open/read/write/ioctl 访问设备 |

普通文件的内容可能持久保存在文件系统中；虚拟文件的读取可能触发内核生成数据。设备节点连接到驱动定义的行为，不代表设备数据都直接存储在节点文件里。

### 3. 本课为什么只观察挂载

课程目标是读懂现有系统关系，不需要格式化任何设备，也无需改 `/etc/fstab`。`findmnt -T` 用来判断某个实际路径属于哪个文件系统；`mount` 的写操作留到具备可丢弃实验介质的专题。

### 常见问题

`df` 与 `lsblk` 显示的数量不同是正常的：有些块设备未挂载，有些挂载没有块设备。找不到固定分区名时先查看本机输出；缺少 sysfs 或 procfs 时确认自己是否处在容器或特殊环境中。
