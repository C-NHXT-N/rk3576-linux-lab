## 跟着做：解释、预测、操作、观察


### 1. 先看整棵树，再讨论局部

```bash
ls -ld / /home /etc /usr /var /tmp /boot /dev /proc /sys
ls -ld /bin /sbin /lib
```

现代 Ubuntu 上，部分传统目录可能是到 `/usr` 的符号链接；不要把图中的名字理解为每个都位于单独分区。具体挂载下一课组会验证。

| 位置 | 主要职责 | 本课程例子 |
|---|---|---|
| `/home` | 普通用户的个人目录 | 源码仓库、练习文件 |
| `/root` | root 账户家目录 | 与 `/` 根目录不同 |
| `/etc` | 系统级配置 | 服务配置、系统身份信息 |
| `/usr` | 大量用户空间程序、库与共享资源 | `/usr/bin/bash`，不等于个人文件夹 |
| `/var` | 经常变化的持久数据 | 日志、服务状态数据 |
| `/tmp` | 临时文件 | 可被清理，不能当长期备份 |
| `/run` | 本次启动期间的运行状态 | PID 文件、运行时套接字 |
| `/boot` | 启动相关文件 | 实际内容依镜像与启动方案而定 |
| `/dev` | 设备节点等访问入口 | `/dev/null`、视频设备 |
| `/proc` | 进程与内核运行信息接口 | `/proc/meminfo` |
| `/sys` | 设备模型及属性等接口 | thermal 温度属性 |

这里先建立职责，后续文件系统课会解释这些内容为什么能共存在一棵树中。

### 2. 从真实文件追溯职责

**先预测：** 用户源码、系统配置、程序可执行文件分别应去哪里找？

```bash
printf '%s\n' "$RKLAB_ROOT"
ls -l /etc/os-release
command -v bash
ls -ld /var/log /run
```

`/etc/os-release` 可能是链接，职责仍是提供发行版身份信息。单个文件的位置不能推出整块磁盘布局。

### 3. 用项目做位置决策

监控脚本源码先放在自己仓库；部署后的系统级 unit 放 `/etc/systemd/system`；服务输出交给 journal；个人实验输出放仓库的 run 目录。源码、配置、日志各有职责，不能因为都有文本内容就混放。

### 常见误区

`/usr` 不是某个 user 的家目录；`/root` 不是 `/`；`/tmp` 不保证跨重启保存；`/proc` 和 `/sys` 的可写接口不属于“任意编辑的普通配置文件”。本课只读系统目录。
