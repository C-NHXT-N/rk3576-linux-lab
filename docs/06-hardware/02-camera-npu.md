# 06-2 摄像头、温度与 NPU 的可用性检查

> 建议时间：20—40 分钟（含独立练习） · 状态：已编写；设备观察已覆盖，物理摄像头采集待验证
>
> 执行位置：除特别标注外，均为 **RK3576 的 Bash 终端**。普通用户执行；带 `sudo` 的步骤才需要管理员权限。
>
> 环境：先按[环境说明](../environment.md)设置 `RKLAB_ROOT`。先修课见页尾“上一课”；首次阅读从课程总目录开始。

## 这课完成什么

- 能按功能识别视频节点，避免把编解码节点当作摄像头。
- 能形成硬件与推理环境检查记录。

## 跟着做：解释、预测、操作、观察


### 1. 接口名称不是能力证明

```bash
ls -l /dev/video* /dev/dri/renderD* 2>/dev/null
command -v v4l2-ctl
```

若安装了 v4l-utils：

```bash
v4l2-ctl --list-devices
```

为自己选择的实际捕获节点查询能力，例如确认节点确为 /dev/video0 后：

```bash
v4l2-ctl --device /dev/video0 --all
v4l2-ctl --device /dev/video0 --list-formats-ext
```

**先预测：** 名为 video-dec0 或 video-enc0 的节点是否必然能接收摄像头画面？不能；它们可能用于编解码。必须确认 Capture 能力、格式、驱动和硬件连接，不能直接把某个节点交给推理程序试运气。

### 2. 先保证输入能用，再引入模型

没有摄像头也可以先走静态图像推理路线，验证模型输入输出后再接摄像头。物理相机接入、格式协商与真实采集必须单独记录结果。本仓库不把缺少相机的检查记成通过。

读取一次真实温度，供未来性能实验比较：

```bash
bash "$RKLAB_ROOT/02-systemd-monitor/rk3576-monitor.sh" --once
```

### 3. NPU 可用需要多个条件同时满足

```bash
python3 -c 'import importlib.util; print({m: bool(importlib.util.find_spec(m)) for m in ["numpy", "cv2", "rknnlite"]})'
ldconfig -p | grep rknn
```

系统 Python 没有包，不代表某个虚拟环境也没有；检查时记录解释器路径。动态库未进入 ldconfig 缓存，也可能通过应用指定路径加载。最终以匹配模型的真实 init_runtime 和 inference 为准。

### 分层排错表

| 层次 | 要确认的证据 | 暂时不能推出的结论 |
|---|---|---|
| 物理输入 | 相机连接与捕获能力 | 任意视频节点均可采集 |
| 驱动与节点 | 绑定信息、访问权限 | 模型一定兼容 |
| 用户空间 | 正确 Python、依赖与 Runtime | 图像预处理一定正确 |
| 模型与输入 | 目标 rk3576、形状、颜色与归一化 | 检测精度达标 |
| 实际运行 | 推理成功、输出合理、日志完整 | 长期运行稳定 |
